# 原则

来源是 DeepSeek Harness 公开文档里反复出现、并且用检查或决策记录钉住的做法。下面是搬到别的项目时仍然成立的部分。

## 常驻上下文是公共资源

根 `AGENTS.md` 每次会话都会占用上下文。它只放站立命令：每条一两行到三行，并链接到真正的说明。

不属于这里的东西：

- 背景故事和复盘
- 操作步骤和例子
- 只在某类任务里才需要的流程
- 从别的文档抄来的同一条规则

字数上限是护栏，不是越短越好的指标。内容还在上限以内时，不要为了再瘦一点删掉契约。超限时的顺序是：搬到别的文档、压缩仍然留在这里的句子、最后才提高上限。提高上限要在同一次改动里说明为什么这些字必须常驻。

子目录的 `AGENTS.md` 只写该子树特有的命令。仓库级规则留在根文件。

## 一条解释一个家

| 事实 | 住在哪 |
|---|---|
| 每次都要遵守的短规则 | 根 `AGENTS.md` |
| 某目录特有的短规则 | 该目录 `AGENTS.md` |
| 某类任务的步骤 | `.agents/skills/` |
| 为什么这样定、放弃了什么 | `.agents/notes/` |
| 当前行为、配置、失败方式 | README、类型注释、代码 |
| 事故经过 | 单独的复盘，不写进常驻指令 |

别处需要长解释时，链接过去，不要再写一遍。使用点仍可保留调用者必须看见的短契约，例如失败后果、权限或不可逆效果；删掉这类局部信息反而会让使用者在行动时看不见限制。模型面对两份会独立演化的解释时，没有可靠办法知道哪份算数。

系统提示和工具说明也一样：身份、模型名、某个工具怎么用，各有一个所有者。工具语义写在工具自己的描述里，不要手写进每份人设。装上或卸下一个工具，不应该再去改人设正文。

模型能从调用结果里学会的失败（文件不存在、发送失败）不必写进工具说明。权限、不可逆效果、必须先做的校验，必须出现在相关动作之前。

## Agent 产品里，模型看见的要能复盘

如果项目会组装模型请求或持久化会话，进入模型请求的内容要能从会话或日志里还原。新的模型可见输入要有对应记录。系统提示如果只活在一个旁路字段里，压缩、计费、回放和「当时模型看到了什么」会各读各的。普通代码仓库不采用这组规则。

用户级指令如果有多份（例如项目一份、全局一份），按内容去重，不要按路径去重。同一文件的符号链接是两条路径、一份正文，按路径去重会打两遍。

未知的提示词变量应该失败，而不是原样送给模型或换成空字符串。静默成功会把拼写错误一直留到有人读记录。

## 决策记录防的是重开争论

代码说明现在是什么。笔记说明为什么是这样，以及没选的路。

- 提议中、已落地、已拒绝要能从路径或文首状态看出来。
- 已落地的笔记用现在时，并在代码改名、改路径时把事实改到和代码一致。不要把旧决定改写成相反的决定；那是新的一篇，两篇互相链接。
- 每篇都写考虑过的替代方案。写不出来就不要装成有过比较。
- 归档后的笔记是冻结历史，不能当现行依据，也不要顺手润色。
- 纯机械修改不写笔记。

## 检查代替自觉

提示词里的「请务必」不会稳定生效。能表述成不变量的规则，做成会失败的检查，并让检查拒绝一个故意写错的例子。

范围要窄：行为改动跑相关测试，文档跑文档检查，外部接口改动才打真实 API。不要为了一次提交把已经通过的全套再跑一遍。CI 负责穷尽和多平台。

报告里只写实际跑过的命令。没跑就说没跑。

沙箱或权限拦截导致命令失败时，保留原命令，用最小的额外权限重试，并保留拦截证据。不能借提权跳过失败的测试，也不能绕过产品自己的沙箱。

## 边界上大声失败

缺配置、缺引用、未知变量，在能判断的最早时刻失败。不要静默跳过。

类型系统已经保证的同一进程值，不要再加一层运行时校验、兜底和恶意输入测试。校验放在不可信边界：解析器、配置、模型或工具返回的 JSON、落盘、子进程和网络。

## 不该照搬的部分

DeepSeek Harness 是一个大 monorepo，有大量专用门禁、双语配对、会话格式版本和插件运行时。小仓库不需要这套门禁。

不要搬：

- 他们的包名、启动方式和覆盖率数字
- 为特定运行时、会话日志、桌面签名写的规则
- 把所有历史决策都留在仓库里的规模
- 为了字数而删掉读者需要的失败方式和所有权

要搬的是分层、单一归属、替代方案，以及会失败的检查。
