# 上下文与工具说明

这是判断标准，不是必须逐步打勾的脚本。

## 先给最少够用的上下文

- 先暴露目的、可用动作和限制。详细步骤在需要时再加载。
- 每个延后加载的材料都要有清楚描述，以及可靠的读取方式。
- 权限、不可逆效果、必须先做的校验，写在相关动作之前。
- 返回短结果，附上标识或路径。不要默认倒出整份日志或文档。
- 结果里带上少量紧邻上下文，例如一段回复附上前面几条消息。省略和截断要标明，并给出继续读取的方法。
- 省上下文只有在不引起更多搜索、重复读取和犯错时才算赚到。

## 工具定义

- 删掉模型会从调用结果里学会的约束。文件不存在而读取失败，不必写成说明。
- 写行为和返回值，不写内部实现、模型已经在结果里看见的标记，以及检查是怎么强制的。
- 默认值、范围、成对出现的参数、何时该设置，写在该参数上。随配置变化的句子通常应该变成参数，而不是写死在总描述里。
- 同一事实只说一次。不在系统提示里重讲工具定义，不在工具描述里重讲参数，不把一个工具的规则写进另一个工具。
- 改完比较首轮提示的 token。变长要有对应删掉的重复，或有必须提前看见的新限制。

## 提示词归属

- 身份、当前模型、工作目录、某个工具的语义，各有一个所有者。
- 人设只写角色和行为。工具怎么选、调用之间有什么习惯，由拥有该工具的说明提供。
- 未知变量、没有值的变量、残缺的占位符，在发给模型之前失败。不要原样留下，也不要换成空字符串。
