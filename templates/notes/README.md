# 决策记录

这里只记录代码、测试和现有文档带不走的取舍：为什么这样、放弃了什么、以后怎样才算被推翻。

## 何时写

同一次变更里新增或更新笔记，仅当取舍会在以后被重新争论。

不写：

- 重命名、移动、格式化
- 没有行为取舍的局部界面调整
- 别处已经写清的规则

更新已有笔记即可，不要为同一个决定再开一篇。决定本身变了，就新写一篇，并互相链接。不要把旧文改成相反结论。

## 路径

`<状态>/<种类>/yyyy-mm-dd-短标题.md`

状态：

- `proposed/`：还没做，或只做了一部分
- `implemented/`：已经落地。用现在时，路径和名字跟着代码更新
- `rejected/`：考虑过并拒绝。只在它还能阻止一个容易重犯的错误时保留

种类从下面选一个：`architecture`、`process`、`testing`、`feature`、`bug-fix`、`simplification`。

## 正文

见 `decision-record-template.md`。每篇都必须有「考虑过的替代方案」。没有记录过的方案就不要编。

## 归档

已落地、又不太可能再指导以后工作、但还有历史价值的笔记，可以整篇冻结到 `archived/`。冻结后不修改、不把它当现行依据。不再有价值的拒绝记录直接删掉，不要留一个空壳。
