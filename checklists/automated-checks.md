# 值得做成自动检查的规则

先做少而快的检查。每条检查都要有一个会失败的反例，否则它只是文档。

## 建议优先

1. 根 `AGENTS.md` 和各子树 `AGENTS.md` 的字数或行数上限。超限失败，而不是警告后继续。
2. Markdown 本地链接指向存在的文件或标题。
3. 决策记录的文首状态和所在目录一致，并且含有「考虑过的替代方案」。
4. 禁止新增已经封掉的写法，例如无说明的 `as unknown`、空 `catch`、硬编码的用户可见文案。
5. 生成文件不被手改。改源头再生成。
6. 文件以一个换行结尾。`git diff --check` 能盖住一部分。

## 检查本身的规则

- 只读工作区，不依赖必须先构建的产物，除非这个门禁明确声明依赖构建。
- 本地针对改动文件，CI 可以全量。
- 例外写在窄的清单里：路径、原因、所有者、到期日。不要为了一处关掉整条规则。
- 上限是护栏。文件已经在限额内时，不要为了压数字继续删契约。

## 先不要做

- 把所有风格偏好都变成失败
- 要求每次提交都跑完整测试矩阵
- 检查注释好不好；这种判断留在 `checklists/writing-checklist.md`
